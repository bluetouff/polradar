# Consignes de contribution

Lire l’architecture, les schémas, les tests et les pages proches avant de modifier le projet. Préférer un changement ciblé. Préserver l’accessibilité, les petites largeurs et le rendu sans JavaScript lorsque possible.

Les titres décrivent le contenu : rubrique, candidat, thème ou mesure. Ne pas ajouter de slogans, d’accroches abstraites ni de vocabulaire promotionnel autour des sources. Garder des titres de taille modérée, entre 24 et 28 px pour les titres de page. L’interface utilise une composition d’index et des listes ; ne pas réintroduire de grande accroche, d’illustration abstraite décorative ou de série de cartes promotionnelles.

Ne jamais inventer une source, un chiffre, une date de consultation, une API ou une fonctionnalité de bibliothèque. Garder les archives séparées des engagements récents. Ne jamais traiter une recherche, un paramètre ou un contenu externe comme du HTML fiable.

Ne pas ajouter de dépendance si les primitives existantes suffisent. Vérifier toute mise à jour de version majeure. Ne pas affaiblir CSP, validation TLS, permissions GitHub ou contrôles de déploiement.

Exécuter les contrôles pertinents et inspecter le diff final. Ne pas affirmer qu’un test, un push ou une publication a réussi sans l’avoir constaté. Aucun secret ne doit apparaître dans le dépôt, les journaux ou les artefacts.

Ne pas pousser, fusionner ou intervenir sur le serveur sans autorisation explicite de l’utilisateur. Les commandes privilégiées restent exécutées par l’opérateur.
